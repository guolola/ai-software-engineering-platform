# 可信生成链路

| 元信息 | 内容 |
| --- | --- |
| 维护状态 | 持续维护 |
| 目标读者 | 产品、开发、测试与课程验收人员 |
| 事实来源 | 生成流水线、运行记录、覆盖矩阵与应用内手册 |

## 概述

平台将需求、可行性、UML、设计、代码、测试和说明书视为有依赖关系的产物链。可信度来自明确的上游基线、可定位的生成记录、结构化校验和必要的人工确认，而不是仅依赖模型回答。

## 当前设计或配置

### 基线与前置条件

需求规则和修复候选需要确认后才能形成稳定输入。下游按钮同时在界面状态与操作守卫中检查前置条件，并展示阻塞原因。

### 运行证据

生成任务保存阶段、状态、事件、错误和可恢复快照。完成结果通过元素 ID、需求规则和上游引用形成映射；失败结果保留可排查信息，而不伪装为成功产物。

### 结构与覆盖

模型输出先经过 JSON、PlantUML 或领域结构的解析与修复，再进入持久化。追踪矩阵和覆盖关系用于发现未覆盖、低置信或断开的链路。

### 人工责任

模型输出仍需人工评审。尤其是需求边界、架构取舍、成本数据、安全结论和验收标准，应由项目成员确认后再作为正式交付依据。

## 操作与维护

1. 先确认需求文本、规则和质量提示。
2. 生成并检查可行性与需求模型。
3. 在设计、代码、测试和文档阶段检查映射与覆盖。
4. 出现失败时从运行历史定位阶段、错误和修复记录。
5. 修改上游后重新验证受影响的下游产物。

## 验证

- 运行 API、Web 和端到端测试。
- 检查每个成功任务都有终态事件和可定位产物。
- 检查失败、重试和恢复不会覆盖已确认的基线。
- 在应用内手册中核对入口、前置条件、产物和映射说明。
