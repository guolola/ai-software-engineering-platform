# 建模能力与图形一致性

| 元信息 | 内容 |
| --- | --- |
| 维护状态 | 持续维护 |
| 目标读者 | 模型维护者、平台开发者、测试与课程验收人员 |
| 事实来源 | contracts 模型契约与语义校验、API 确定性绘制器、编辑器和回归测试；OMG UML 2.5.1 与 PlantUML 官方文档 |

## 概述

平台支持按阶段限定的建模子集。UML 语义依据 [OMG UML 2.5.1](https://www.omg.org/spec/UML/2.5.1/About-UML)。系统上下文、功能分解树、界面结构与导航、物理表模型使用各自的建模约定，不宣称它们是独立的 UML 标准图类型，也不宣称完整覆盖 UML。

结构化模型是业务语义的唯一来源。成功生成必须同时满足阶段契约、图结构与语义校验、确定性绘制及渲染要求。图像审查提供辅助反馈；能生成 SVG 不能证明模型正确。

## 当前设计或配置

### 阶段能力

| 阶段与模型 | 主要元素 | 关系与限制 |
| --- | --- | --- |
| 可行性系统上下文 | 目标系统、人员、外部系统 | 目标系统与外部参与方的有向或双向交互；不引入内部技术组件 |
| 可行性业务流程 | 动作、判断、合并、分叉、汇合、起止节点与泳道 | 控制流；单一起点、目标系统泳道、业务节点来源属于平台约定 |
| 需求功能结构 | 功能 | 唯一分解关系构成单根、单父、无环的树 |
| 需求用例 | 参与者、系统边界、用例及扩展点 | 参与者与用例关联；用例包含、扩展；同类元素泛化；扩展指向基础用例并引用其扩展点 |
| 需求领域概念 | 业务概念类、属性、枚举 | 关联、泛化、聚合、组合；不开放技术接口、方法、实现和技术依赖 |
| 需求分析顺序 | 参与者、边界、控制、实体对象 | 同步、异步、返回、创建、销毁与组合片段；表达业务职责，不默认推导实现分层 |
| 需求活动 | 动作、对象、输入输出引脚、控制节点、两类终止节点、泳道 | 控制流与对象流分离；允许循环、并发和同名动作 |
| 需求部署约束 | 已知设备、执行环境、外部系统 | 通信及已有环境限制；不预设 Kubernetes 等技术方案，不放入制品和实现组件 |
| 需求原型界面 | 页面、入口、模块 | 自定义结构与导航；包含、导航、打开、提交、返回、模块依赖 |
| 设计逻辑架构 | 可嵌套包、归属包的组件 | 包含归属、依赖、通信；包含由嵌套绘制；缺失包引用报错 |
| 设计交互顺序 | 实现对象、消息、片段、独立激活区间 | 同步、异步、返回、创建、销毁；alt/opt/loop/par 的显式分支与嵌套 |
| 设计页面导航 | 页面、入口、模块，页面路由 | `navigation` 类型；与原型相同的关系种类，向代码映射页面、路由和模块 |
| 设计类 | 类、接口、枚举、属性、操作 | 关联、依赖、泛化、实现、聚合、组合；角色名、多重性、可导航性、抽象与静态标记 |
| 设计组件 | 组件、带操作的接口 | 依赖、接口提供与使用、组合、通信；组合表示整体拥有部件，通信表示组件间交互 |
| 设计部署 | 设备、执行环境、制品、逻辑组件、外部系统 | 节点嵌套表达承载；制品部署到节点、体现逻辑组件；依赖与通信保留方向、协议和端口 |
| 设计物理表 | 表、字段、主键、唯一约束、外键、检查约束 | 联合主键、复合外键与两端基数；多对多使用关联表及两组外键 |

独立状态机、关联类、复杂组件端口与连接器不在当前开放范围内。每张物理表一个主键、活动显式起止节点、控制节点不混接对象流和控制流等限制属于平台支持子集，不应解释为 UML 或 SQL 的通用要求。

### 唯一契约与无损校验

[`models.ts`](../../packages/contracts/src/models.ts) 定义结构；[`model-semantics.ts`](../../packages/contracts/src/model-semantics.ts) 按阶段选择契约并维护端点矩阵、标识与引用、层级、对象类型、片段及键约束。提示词、供应商输出结构和编辑表单均从同一份契约派生。保留 Zod 3；递归一致性测试检查嵌套字段和枚举。

诊断包含模型、字段路径、元素标识、问题代码及说明。结构化与普通 JSON 输出使用同一校验。普通规范化仅移除供应商为缺省字段提供的 null 等格式占位；未知字段、非法端点、缺失引用不会被静默删掉。结构错误最多修复两轮，仍不合法则报告失败。禁止根据动作名称改为终止、自动补造业务边或节点、把 alt 降为 opt、删除完整循环，以及截断条件和约束。

物理表的 `relationalConstraints` 是主外键唯一来源。列标记、单列引用与 ER 连线是派生结果，生成端不单独请求它们，编辑器通过修改约束维护它们。复合外键按字段顺序匹配目标的主键或唯一键，并校验类型、可空性。SQL 约束含义参考 [PostgreSQL 约束文档](https://www.postgresql.org/docs/current/ddl-constraints.html)，平台不执行检查表达式。

顺序图片段必须覆盖连续消息；分支互不重叠并完整覆盖所属片段，可用空分支表达不执行操作的替代路径。子片段声明父片段，位于父片段的分支时还需声明父分支。替代分支的生命线状态分别校验，分支后无条件消息必须在各条可能路径上合法。独立或嵌套激活允许；激活必须在同一分支结束或完整包围片段，交叉激活和交叉片段不支持；并行分支同时改变同一生命线生命周期时报错。

### 原生语法与平台映射

| 内容 | 绘制方式与边界 |
| --- | --- |
| 用例、类、顺序、包、部署与表外观 | 使用 PlantUML 对应声明、箭头、片段及嵌套；语义正确性由公共校验保证 |
| 活动图 | 显式节点与逐条连线的图形映射，不进行顺序遍历或自动连接；`renderMapping.mode` 为 `explicit-graph` |
| 动作引脚 | 使用矩形端点外观表达活动的输入输出引脚；内部绘制关键字不会改变引脚的活动模型归属，不开放为组件端口 |
| 活动终止 | 圈内实心圆代表整个活动结束，圈内叉代表当前分支结束；不会合并终止节点 |
| 组件接口操作 | 使用带操作区、标记 `interface` 的分类器外观，与组件的提供/使用关系配合 |
| 聚合或组合的反向可导航性 | 保留菱形和正向箭头；菱形端使用 `{navigable}` 明确标注，避免使用当前引擎不支持的叠加箭头 |
| 系统上下文、功能树、页面导航 | 平台自定义图形映射，分别表达边界交互、分解、页面导航与包含 |

[PlantUML 活动图文档](https://plantuml.com/activity-diagram-beta) 的对象外观不等价于完整 UML 对象流语义。平台根据显式对象、引脚、类型和端点检查对象传递；当前不实现完整 UML token 执行引擎。类、组件和顺序图表示分别参考 [类图](https://plantuml.com/class-diagram)、[组件图](https://plantuml.com/component-diagram)、[顺序图](https://plantuml.com/sequence-diagram) 官方文档。

绘制器将元素原始标识确定性编码为无碰撞别名，记录元素与关系输出映射并检查遗漏或重复。返回导航保持模型的起点到终点；创建消息使用创建生命线语义；无效包归属不得导致组件消失。条件、触发、守卫及约束可换行但不删节。语义修改回到模型修复，再重新绘图，不允许 LLM 任意改写最终 PlantUML。

## 操作与维护

1. 调整支持范围时先修改阶段契约与公共语义，再更新绘制、编辑和下游映射。
2. 编辑关系时先选择类型，再选择合法端点。用例归属与扩展点、活动引脚、顺序分支与激活、包和节点归属、表约束在对应元素表单维护。
3. 消息列表可调整顺序；改变顺序后需同步修正片段和激活引用。删除节点留下的关系会显示诊断，由用户明确修正；无效草稿不持久化、不重绘覆盖有效结果。
4. 设计阶段使用 `navigation`，需求阶段保留 `activity`。同步维护模型列表、依赖、追踪、文档、导出和设计到代码映射。
5. 业务对象与对象流参与追踪；起止、泳道、引脚、激活等辅助结构不要求独立覆盖每条需求。
6. 输入指纹使用 `fp:v3`。不将旧指纹自动升级为新结果，不提供旧项目模型兼容分支、迁移、批量升级或历史清理。

## 验证

- 每个阶段模型具备合法和非法端点样例；结构字段、枚举与供应商结构递归比对。
- 18 类已复现绘图问题覆盖边界、别名、方向、角色、多重性、对象流、片段、包、部署与表约束。
- 用仓库实际 PlantUML JAR 编译样例，并断言输出的元素标识、连线端点、箭头与完整语义文本；不能仅检查退出码。
- 活动覆盖循环、并行、同名动作、跨泳道、多个引脚与两类终止；顺序覆盖替代路径生命周期、自调用、嵌套与激活；表覆盖联合键、复合外键及派生基数。
- 执行 `npm run test:contracts`、`npm run test:api`、`npm run test:render`、`npm run test:web`、`npm run typecheck:web`，文档执行 `npm run audit:docs`。
