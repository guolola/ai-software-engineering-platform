# Coding Agent 接入与授权

## 适用场景

把平台保存的完整设计、独立验收条件、工程约束和测试交给编程助手，让它在你的代码仓库中 **实现功能、核对已有代码、补充测试，或同步需求变更**。MCP 是助手读取这些资料的连接方式。

### MCP 具体能做什么

平台目前提供以下 **4 个只读工具**。你可以直接用自然语言给助手布置任务，由助手调用工具，无需手动填写接口参数。

| 你想完成的事 | 助手使用的工具 | 获得什么 |
| --- | --- | --- |
| 找到要处理的项目 | `list_projects` | 搜索账号已获授权且仍可访问的项目，返回名称、描述和项目标识 |
| 了解实现范围与依据 | `get_implementation_context` | 整个项目或指定需求、产物的资料目录，以及依赖、缺失项和版本清单 |
| 阅读完整设计、验收条件、工程约束或测试 | `get_artifact` | 按目录里的产物标识和版本读取完整内容；内容较长时分段读取 |
| 检查上次实现后有什么变化 | `check_context_updates` | 比较已应用的版本清单，报告资料的新增、修改、删除或过期变化 |

> [!NOTE]
> 这四个工具提供实现依据。编写文件、安装依赖、运行程序和执行测试，由你使用的编程助手在外部仓库中完成。

## 入口位置

项目列表左侧 **编程助手**，或直接打开[编程助手页面](/projects/connections)。页面包含 **MCP 客户端、接入指南、使用案例、连接记录**。

## 前置条件

- 已登录，平台已启用 MCP。可以先连接，再创建或加入项目。
- 已保存本次实现所需的完整设计、验收条件和工程约束。输入框里尚未提交的草稿不会自动进入 MCP。
- 已安装要使用的客户端，并准备本地代码仓库或明确的新项目目录。
- 告诉助手你的实现范围、技术要求和验收目标；已有仓库时，先让它检查现有结构。

平台负责需求到设计的正确性和完整性，编程助手按设计实现。可以先连接，但开始某项实现前应具备该范围所需的设计；设计缺失、冲突、待确认或过期时，应反馈平台补齐，不从需求重新推导设计。

## 操作步骤

### 1. 打开对应客户端的接入指南

在 **MCP 客户端** 中找到你使用的工具，点击 **查看接入指南**。复制页面提供的 **MCP 地址**，按弹窗中的桌面端或命令说明配置。

![当前编程助手页：MCP 客户端目录和查看接入指南入口](/help/images/docs-coding-agent.png)

不同客户端支持的连接方式不同，以该卡片的指南和官方说明为准。

![接入指南：按客户端说明复制 MCP 地址并配置连接](/help/images/docs-coding-agent-setup.png)

### 2. 完成授权并确认范围

| 连接方式 | 怎么操作 | 可读项目与有效期 |
| --- | --- | --- |
| **浏览器授权** | 在客户端发起连接，在平台授权页登录并点击 **授权读取全部项目**，无需选择项目 | 账号当前有查看权限的全部项目，包括之后创建或加入的项目；授权有效期 30 天 |
| **个人令牌** | 填写连接名称，点击 **创建 30 天个人令牌**，将令牌保存到客户端凭据设置 | 页面创建的令牌可读账号当前有权限的全部项目，包括之后创建或加入的项目；有效期 30 天 |

> [!WARNING]
> 个人令牌只展示一次。保存到客户端凭据设置或环境变量，不要提交到代码仓库。授权被撤销、到期或项目成员权限失效后，后续读取会被拒绝。

两种方式都随账号当前项目权限变化。已有的限定项目连接保留原范围，重新授权后使用账号范围。

### 3. 告诉助手你要做什么

按 **说明任务 → 列出依据与缺口 → 完整读取并核对 → 变化后刷新** 的顺序开始：

1. 告诉助手项目名称和本次要做的功能，让它先找准项目；遇到同名项目，由你确认。
2. 要求助手列出已有的完整设计、验收条件、工程约束和测试依据，并说明哪些内容缺失、冲突、待确认或需要更新。
3. 让助手完整读完相关资料，核对当前仓库，再说明准备实现的范围和验证方法。
4. 如果阅读或开发途中修改了平台资料，让助手重新读取并核对，避免混用修改前后的内容。

> [!TIP]
> 分页、长内容分段读取和版本校验由助手处理，你无需手动填写接口参数。只做一个功能时，助手也可能需要读取相关依赖与全局约束；发现来源缺失时，应先检查项目资料是否遗漏。

### 4. 从一个明确任务开始

页面的 **使用案例** 提供首次实现、同步变更、单个功能和代码核对等提示词。替换项目名称后，即可交给助手。

**首次实现一个功能：**

```text
我要处理的项目是“图书馆预约系统”，本次只实现“学生提交预约”。
请先通过 MCP 查找项目；若重名，先让我选择。
检查当前仓库，再读取该功能完整设计、验收条件、工程约束和已保存测试。
说明缺失、冲突、待确认或过期的依据，按已保存设计确认实现边界；设计与仓库技术约束冲突时反馈平台确认，不自行重做设计。
运行可用测试，报告已通过、失败和未验证项，并记录实际已应用的来源版本。
```

**平台资料更新后继续开发：**

```text
请读取当前仓库的 .uml-platform.json，核对服务地址与项目，
使用 MCP 检查上次已应用资料之后的变化，再读取发生变化的完整内容。
仅调整受影响功能与测试，保留我的已有修改。
验证后只更新确实已应用的来源版本；失败或中断时保留此前记录。
```

首次接手没有版本记录时，助手应说明无法直接比较“上次版本”，先读取当前依据并检查代码，不应把全部代码视为未完成。

![使用案例：展开需要的任务，复制提示词并替换为自己的项目与目标](/help/images/docs-coding-agent-examples.png)

### 5. 分别验证连接与实现结果

回到 **连接记录** 查看 **最近成功调用**。显示 **连接成功**，说明服务端记录了成功的 MCP 工具调用。

代码是否完成、能否运行、测试是否通过，要看外部助手给出的文件变更和实际验证结果。不再使用的连接可点击 **撤销**。

## 结果与产物

平台侧保留授权范围、到期时间和最近成功调用记录。外部仓库中则由助手产出代码、测试与验证说明。

开始实现前，助手读取任务包及当前任务关联的全部完整设计、工程约束、验收条件、测试和问题提示。交付验证前，再获取报告模板和验证器下载信息；由本地程序下载验证器、校验文件哈希并保存后运行。验证器源码不需要通过模型解码或逐字复制，下载和验证均不会让平台执行你的本地代码。

助手完成后，可用自身文件工具在仓库根目录维护 `.uml-platform.json`：记录服务地址、项目、读取范围及已应用的来源版本清单（`appliedManifest`）。后续同步据此检查变化。

> [!NOTE]
> MCP 服务不会替你创建这个本地文件。记录中不应保存令牌、密码或项目私有正文；任务失败或中断时保留此前版本，部分完成时只记录确实已应用的资料。

**连接成功不等于助手持续在线，也不等于实现完成或测试通过。**

## 映射关系

### 哪些已保存资料可以读取

| 平台资料 | MCP 提供的内容 | 助手如何使用 |
| --- | --- | --- |
| 独立验收条件 | 从已保存原子需求提取的验收条件、需求 ID | 验证设计实现是否满足验收标准 |
| 工程约束 | 已保存的实施环境、技能与资源等约束 | 确认实施环境与工程限制 |
| 完整设计模型 | 结构化设计、PlantUML 源码、追踪 ID 与上游版本 | 直接指导架构、交互、类、页面、数据库和部署实现 |
| 测试 | 已保存测试用例与覆盖关系 | 补充和执行本地测试，检查业务覆盖 |

通过 MCP 使用已保存设计与验收条件，即视为平台认可这些实现依据。无论审核问题是否修复，审核意见、确认状态、修复历史和修复候选都留在平台，不传给编程助手，也不作为后续任务的阻断条件。

需求模型、原始需求、业务规则正文、质量报告、分析图和候选方案不会传给编程助手。上游变化仍会通过追踪 ID、版本哈希与过期状态反映到设计，不传上游正文。

### 如何判断资料是否仍有效

目录中的 `current` 表示来源版本仍匹配，`stale` 表示上游已变化，`unknown` 表示无法确认时效。助手按平台已保存的设计与验收条件实现，处理缺失模型、无效引用和过期版本等实际问题，并验证本地代码与测试。

设计模型是代码的直接依据。遵守设计技术约束和明确工程环境；与现有仓库冲突时反馈并确认设计，不自行重做设计。平台原型的 React、Sandpack 或仅前端限制不进入上下文。

## 常见问题

**MCP 能替我在平台生成模型、修改需求或保存文档吗？** 不能。这四个工具只读取资料与检查变化，不提供平台资源新增、修改、删除、需求确认或生成流水线调用。先在平台完成相关操作并保存，再让助手刷新资料。

**可以下载说明书、读取运行历史或直接拿到图片吗？** 当前四个工具不提供 DOCX/SVG 文件下载、文档库或运行历史读取。它们读取结构化内容与图源码，也不会提供供应商密钥；文件下载请使用对应平台页面。

**资料缺失或图与模型不一致怎么办？** 工具会返回缺失、未知或冲突提示，不会自动补齐或修复。助手应说明差异，反馈平台补齐或确认设计；只实现设计明确的部分，不从需求自行补设计。

**为什么一直显示待验证？** 授权还没有产生成功调用。让助手实际查找项目并读取资料，再检查连接记录。读取失败时检查授权、到期时间和项目权限。

**旧客户端仍记录需求模型或原始需求怎么办？** 刷新上下文后，旧来源会显示为删除。重新获取实施包、生成本地快照并更新报告的来源引用，保留已有代码和测试。

**为什么需求改了，助手还用旧资料？** 连接不会自动推送项目变更。继续开发前让助手运行 `check_context_updates`，读取变化并更新真正应用的版本记录。

**为什么指定一个功能后仍返回其他资料？** 范围读取会保留全局工程约束，并补入设计依赖及关联验收条件，帮助助手实现该功能；缺少追踪关系的内容仍需从整项目目录确认。
