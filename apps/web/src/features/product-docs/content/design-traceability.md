# 检查需求到设计的覆盖

## 适用场景

确认需求是否落实到设计，或查找缺失、低置信和待复核的来源关系。

## 入口位置

展开左侧设计模型，打开 **跟踪矩阵**；顶部 **链路图** 用于查看跨阶段关系。

## 前置条件

已有需求模型和设计模型。完整映射需要保存有效的元素级来源关系。

## 操作步骤

1. 选一项重要需求，例如“同一学生同一时段不能重复预约”。
2. 在需求模型的 **跟踪矩阵** 找到对应元素。
3. 在设计模型的 **跟踪矩阵** 检查该元素对应哪些设计内容。
4. 打开目标元素，检查设计是否实际包含约束或行为。
5. 对缺失或待复核关系，回到需求或设计页面修正；再检查 **链路图** 中的相关结果。

> [!NOTE]
> 连线存在不等于设计已正确实现需求。还需要打开设计内容，核对具体行为与约束。

## 结果与产物

得到需求元素与设计元素之间可核查的对应关系，并能定位哪些内容未覆盖或需要人工审阅。

## 映射关系

| 需求内容 | 可以检查的设计内容 |
| --- | --- |
| 提交预约 | 预约用例实现中的调用顺序 |
| 学生、座位和预约对象 | 设计类与数据库表 |
| 预约成功通知 | 通知组件或服务职责 |
| 重复预约限制 | 服务校验与数据库约束 |

## 常见问题

**矩阵为空？** 确认模型已成功生成。旧结果可能缺少元素级映射，需要更新需求模型与设计模型。

**映射不准确？** 先检查原需求是否明确，再核对来源与目标元素；不要依靠相似名称直接认定覆盖。

**下游缺少内容？** 在 **链路图** 找到缺失或过期阶段，返回对应页面处理。

**怎么检查代码是否遵循设计？** 通过[编程助手](coding-agent.md)读取资料，在外部仓库中核对实现并执行测试。
