# 可行性分析：系统上下文图、实现方案与研究报告

## 适用场景

在需求规则确认后，用可行性分析比较实现路线、成本收益、风险和结论，并形成可交付报告。

## 入口位置

进入项目工作台，在需求阶段打开“可行性分析”。入口会根据需求规则和当前产物状态展示可执行动作或阻塞原因。

## 前置条件

- 项目已有需求文本。
- 需求规则已经生成并确认。
- 当前模型 Provider 可用，且账号具备相应生成权益。

## 操作步骤

1. 生成系统上下文图，检查系统、外部参与者和边界关系。
2. 生成候选实现方案，逐项检查技术路线、资源、成本收益和风险。
3. 编辑并确认采用方案与五类可行性结论。
4. 生成可行性研究报告，检查图表、方案和结论是否为最新版本。
5. 上游需求或方案变化后，根据页面提示重新生成受影响产物。

## 结果与产物

- 系统上下文模型与可渲染图
- 一个或多个候选实现方案
- 成本收益、风险与可行性结论
- 可行性研究报告及其版本

## 映射关系

系统上下文元素和实现方案都应引用已确认的需求规则。可行性报告汇总当前有效的上下文图、方案、风险和结论；任一上游产物变化都可能使旧报告失效。

## 常见问题

**为什么生成按钮不可用？**

先查看按钮旁的阻塞原因，通常是需求规则未确认、Provider 不可用、权益不足或已有任务正在运行。

**修改方案后为什么提示报告过期？**

报告是方案与结论的下游快照。修改上游后需要重新生成报告，才能保证内容一致。

**系统上下文图渲染失败怎么办？**

先从生成任务或运行历史查看 PlantUML 错误，再尝试页面提供的修复或重新生成操作。
