# 可行性分析：系统环境图、业务流程、实现方案与研究报告

## 适用场景

在需求规则确认后，用可行性分析比较实现路线、成本收益、风险和结论，并形成可交付报告。

## 入口位置

进入项目工作台，在需求阶段打开“可行性分析”。入口会根据需求规则和当前产物状态展示可执行动作或阻塞原因。

业务与系统流程图保存完整后，侧边栏提供“跟踪矩阵、元素、关系”子菜单。详情页与系统环境图共用预览图、元素清单和关系说明布局；可搜索、筛选元素和关系，点击元素在图中定位，并导出 SVG 或 PlantUML。跟踪矩阵单独展示泳道、节点与连接关系的需求来源，缺失或失效的来源不会自动补成有效映射。

## 前置条件

- 项目已有需求文本。
- 需求规则已经生成并确认。
- 真实项目已选择可用的模型供应商及其目录中的模型，且账号具备相应生成权益；服务端配置的离线演示项目无需选择模型。

## 操作步骤

1. 生成系统环境图，检查系统、外部参与者和边界关系。
2. 选择“业务与系统流程图”，根据已确认需求生成泳道活动图。检查人员操作、系统处理、条件分支和来源规则；该图也可独立生成，无需先生成系统环境图或需求模型。
3. 选择“实现方案”，系统自动勾选缺失或过期的前置图，按“系统环境图 → 业务与系统流程图 → 实现方案”生成，已有有效图直接复用。前置图失败时不会继续生成方案。
4. 编辑并确认采用方案与五类可行性结论。
5. 生成可行性研究报告，检查图表、方案和结论是否为最新版本。
6. 上游需求或方案变化后，根据页面提示重新生成受影响产物。

## 结果与产物

- 系统环境模型与可渲染图
- 业务与系统流程图：核心业务闭环的泳道活动图、规则追踪、SVG 与 PlantUML 导出
- 两个生成的候选实现方案
- 成本收益、风险与可行性结论
- 可行性研究报告及其版本

## 映射关系

系统环境元素、流程图中的业务动作和判断、实现方案都应引用已确认的需求规则。人员与外部系统泳道也需有规则依据。业务与系统流程图独立保存，需求变化后会标记过期，不会覆盖需求模型阶段的活动图。

实现方案同时使用已确认需求、系统环境图、业务与系统流程图和补充资料。系统环境图确定系统边界与外部集成，流程图确定业务顺序、人员职责、系统处理和分支，进而形成模块职责、风险及里程碑验收条件。

可行性报告沿用现有排版，汇总当前有效的系统环境图、方案、风险和结论，流程图可独立查看和导出。生成报告前同样检查两张图及方案是否有效；流程内容或规则追踪变化后需要重新生成方案，单纯重新渲染图片不会使方案过期。

## 常见问题

**为什么生成按钮不可用？**

先查看按钮旁的阻塞原因，通常是需求规则未确认、模型供应商或模型未选择、所选模型已下线、权益不足或已有任务正在运行。模型未选择时仍可操作模型选择器；从当前供应商目录选择有效模型后恢复生成。离线演示项目免选模型，但仍需满足需求与产物依赖条件。

**修改方案后为什么提示报告过期？**

报告是方案与结论的下游快照。修改上游后需要重新生成报告，才能保证内容一致。

**为什么业务与系统流程图没有串起所有功能？**

图中优先展示有需求依据的核心业务闭环。互不相关的功能不会被强行连接，无法确定的步骤或范围会记录在图的说明中。

**为什么侧边栏没有业务与系统流程图？**

概览始终保留生成卡片；模型、PlantUML 和 SVG 全部保存成功后才显示侧边栏菜单。首次失败或取消不显示菜单，已有图过期或重新生成失败时仍可查看旧图及状态提示。

**旧项目的实现方案为什么需要重新生成？**

历史图和方案会保留。未使用流程图生成的旧方案会提示补齐依赖；点击“补齐依赖”进入已勾选所需产物的概览。保存文字修改不能将未结合最新流程的旧方案恢复为最新状态。

**系统环境图渲染失败怎么办？**

先从生成任务或运行历史查看 PlantUML 错误，再尝试页面提供的修复或重新生成操作。
